# Planned visit recovery

Review results keep the saved, queued and needs-attention counts beside each visit. A queued visit is still unconfirmed. **Open Pending Sync** opens the app’s existing sync review so the user can check whether it is waiting, syncing or needs attention. **Check saved visits** makes a user-triggered `get_dog_history` read and marks a queued row saved only when Dog ID, Stay ID, dates and confirmed booking type all match exactly. The check reads history once per Dog ID, then checks each queued visit against that response. A failed or ambiguous read leaves the row queued. When an unknown Dog ID must be resolved, the check continues only if the exact dog name has one matching identity. No polling runs.

**Resume other visits** skips every queued row and keeps each original stay ID and mutation ID. If a queued new-dog visit has no confirmed Dog ID yet, its other visits wait too, so they cannot create a second dog identity. After the exact queued stay is confirmed, remaining rows can use that returned Dog ID; saved rows stay skipped and saved care choices stay in their original payloads.

The sync queue marks an item `queued`, changes it to `syncing` during a send, and marks a rejected or unrecoverable item `conflict`. A successful response removes the item from the local queue, but does not send a reconciliation result back to the in-memory booking plan. That removal alone never changes a result to saved. The explicit check reads the backend’s dog history and requires the exact booking identity. The history response does not include a newly prepared care link, so a reconciled stay does not gain a sharing action; prepare a missing link later from Owner Care Link in Care.

If the sync review reports a conflict, use that queue’s existing review flow. Keep the original plan open while reviewing; do not make a replacement plan for a visit that may already have saved.

Browser coverage uses synthetic writes. It checks a mixed saved/queued/error recovery sequence, confirms that Resume keeps the original payloads and does not resubmit queued rows, and verifies that Check saved visits requires an exact server match. It also checks the queued recovery actions at 320, 390 and 1440px in light and dark themes, including keyboard focus and touch target size. This does not verify a real booking write or a production queue reconciliation.
